# 0003 driftmark is written in Rust

> Short version: one Rust program, published to npm, PyPI, crates.io and Homebrew. The design comes from a private Go prototype. No code is copied from it.

## Situation

A private Go prototype (about 3,800 lines) already renders a docs folder and shows per-block changes. driftmark needs a server, notes, an MCP connector, search, a status view, presets and exports on top of that, so most of version 1 is new code in any language. The maintainer does not read code. Agents write it.

## Options

| | Go | Rust | TypeScript |
|---|---|---|---|
| Reuse | About 2,400 prototype lines after a restructure | Rewrite, design kept | Rewrite |
| Mistakes caught before the program runs | Medium | Strongest: unhandled cases and empty values do not compile | Weakest |
| Markdown parser | goldmark: block start positions only | comrak: start and end of every node, 652/652 spec tests, can write Markdown back | remark: full positions |
| D2 diagrams | Native library inside the program | Separate `d2` program, or an 11.5 MB browser file | 31.7 MB package |
| Mermaid diagrams | Browser only | Server-side with `merman` (used by the Zed editor), browser as fallback | Browser, or a headless Chrome |
| Runs inside editors and browser pages later | Poor | Best: WebAssembly, Node (napi-rs) and Python (pyo3) from one core | Native for VS Code and Obsidian, no Python |
| MCP library | Stable since 2025 | `rmcp`, three major versions in 2026 | Stable reference SDK |
| Install for others | Proven (esbuild, lefthook) | Proven (Ruff, uv, Biome, and cj-ways/acctswap) | npm native, heavy elsewhere |

## Decision

Rust. The reasons:

1. The change review engine is the product (decision 0001). Rust lets the same engine run later inside editors, browser pages and Python tools without a second rewrite.
2. The maintainer does not read code. Rust's compiler stops more agent mistakes before they reach him.
3. Mermaid can be drawn on the server, which keeps phone pages light and lets the lint check diagrams.
4. The Go advantages were smaller than they looked. Most of version 1 is new code, and the maintainer's corpus has no D2 diagrams.

The prototype's design is reused: blocks, pairing, the "words kept in order" view choice, move detection and the formatting-only fold. Its source code is not copied.

## What this costs

- A slower first version than a Go restructure. A research agent guessed 2 to 4 weeks of agent work for the engine. That is a guess.
- D2 needs the `d2` program installed; without it a D2 block shows as code.
- `rmcp` changes often. driftmark keeps its MCP code behind a thin layer and pins the version.
- Builds are slower than Go, so agents wait longer per change.
